# plans/

One directory per showcase drawing, named by slug:

```
plans/<slug>/
  plan.arch          the source — the drawing's only hand-written file
  README.md          the story: what it is, what the compiler says about it
  social.json        hand-written — copy and framing for `npm run social <slug>`
  overlay.json       hand-written, optional — annotations for `npm run overlay <slug>`
  plan.svg           generated by `npm run render <slug>`
  plan.png           generated, 1600px wide, white ground
  plan.L<n>.svg/png  generated, one pair per storey (multi-level plans only)
  plan-annotated.*   generated by `npm run overlay <slug>`
  cover.svg/png      generated by `npm run social <slug>` — 1600x900
  code.svg/png       generated by `npm run social <slug> -- --mode code`
  lint.txt/.json     captured CLI output, quoted verbatim by README.md
  describe.json      captured `arch describe --json`
  suggest.txt        captured `arch suggest`
  fix-dry-run.txt    captured `arch fix --dry-run`
  graph-check.txt    captured `arch validate --graph` (skeld only)
  NOTES.md           optional — sources consulted, liberties taken, scale notes
```

Hand-written: `plan.arch`, `README.md`, `social.json`, `overlay.json`, `NOTES.md`, and two one-offs
— `skeld/intended-graph.json` (the adjacency `validate --graph` is checked against) and
`tweet-house/plan-strict.arch` (the 145-byte golf entry). Everything else is generated or captured.
Never hand-edit an SVG, and never hand-edit a captured `.txt`/`.json`: change the source, re-render,
and re-run the command the plan README's reproduce block names.

A plan that `import`s a shared component keeps it in `plans/<slug>/lib/` — import paths resolve
relative to the plan file.
